# iur-ade-generator

Code generators and verification harness for the i-UR ADE (PLATEAU, CityGML 2.0) extension of
[citygml4j](https://github.com/citygml4j/citygml4j) and the 3D City Database Importer/Exporter:

- [iur-ade-citygml4j](https://github.com/kei-w/iur-ade-citygml4j) (branches `iur-2.0`, `iur-3.0`, `iur-3.1`, `iur-3.2`)
- [iur-ade-citydb](https://github.com/kei-w/iur-ade-citydb) (the same branches)

The generators read the i-UR XSDs (`uro`, `urf`), the JAXB classes generated by ade-xjc and the 3DCityDB schema mapping,
and write the model classes, (un)marshallers, importers, exporters, schema registrations, the schema mapping of the
modules the ADE Manager cannot transform, a fixture file that uses every attribute, and the CHANGES sections of both
forks. The harness imports the fixture into a 3DCityDB, exports it again and compares the result.

The design is described in the investigation documents of the `plateau-citygml-ade-investigation` workspace (08: all
attributes, 11: ADE feature types, 12: urban function module); the main decisions are summarised in [Design](#design).

## Requirements

- Python 3.14 and [uv](https://docs.astral.sh/uv/) (`uv sync --dev` installs the Python version of `.python-version` and
  the development tools).
- The two forks checked out next to this repository (`../iur-ade-citygml4j`, `../iur-ade-citydb`); the scripts switch
  them to the branch of the edition.
- JDK 11 for the forks and the Java harnesses (Gradle wrapper); the forks pin it with `mise`.
- For the full regeneration and the round trip (`scripts/regen_edition.sh`): ade-xjc 2.10.0, the 3DCityDB
  Importer/Exporter 5.5.0 with the ADE Manager plugin 2.3.0, the 3DCityDB 4.4.1 SQL scripts, PostgreSQL/PostGIS and
  `psql`. The scripts still take these from the paths of the development machine (`D:\Tools\...`,
  `localhost:35432`); moving them into a configuration file is the next step of the migration.

## Usage

```bash
uv sync --dev
uv run iur-ade --help
```

| Command | Purpose |
|---|---|
| `iur-ade patch-binding <citygml4j repo>` | JAXB property renames in `binding.xjb` (feature types, urf package, `lod-N` elements) |
| `iur-ade patch-mapping <citydb repo> <citygml4j repo> <version> [modules]` | fixes of the ADE Manager output (idempotent): ifc choice/inline types, injections, top-level flags, join tables for multi-valued data types, cascading subtype keys, `core:_CityObject` hooks |
| `iur-ade gen-mapping <citydb repo> <citygml4j repo> <version> urf uro` | schema mapping and DDL of a module the ADE Manager cannot transform (urf 2.0/3.x), merged into the citydb resources |
| `iur-ade gen-citygml4j <citygml4j repo> <citydb repo> <version> all uro,urf` | model classes, JAXB (un)marshallers, walkers and modules |
| `iur-ade gen-citydb <citydb repo> <citygml4j repo> <version> all uro,urf` | importers, exporters, join table importers and schema registrations |
| `iur-ade fixture <citygml4j repo> <citydb repo> <version> all <out.gml> uro,urf` | a CityGML file with one feature per hooked CityGML feature type and per ADE feature type, every attribute populated |
| `iur-ade compare <original.gml> <roundtrip.gml> [--db] [--subset]` | semantic comparison of the city objects of two files (`--db` neutralises the known Importer/Exporter round-trip differences, `--subset` ignores extra objects) |
| `iur-ade changes-features ...`, `iur-ade changes-urf ...` | CHANGES.md sections of both forks (idempotent) |

The whole chain of one edition, including the JAXB classes, the builds, the extension folder, a fresh verification
database, the fixture round trip and the XSD validation:

```bash
bash scripts/regen_edition.sh 3.1
```

Other scripts: `scripts/recreate_db.sh` (drop and recreate a verification database and register an extension folder),
`scripts/roundtrip_batch.sh` (round trip of every CityGML file of a folder through citygml4j only),
`scripts/db_roundtrip_batch.sh` (import a list of files into a fresh database, export everything and compare each
file), `scripts/tag_editions.sh` (annotated tags of the four editions in both forks and their distributions).

The Importer/Exporter cannot load two editions of the extension at once, so they live in separate folders
(`ade-extensions-iur20` ... `ade-extensions-iur32`) and are selected with `--ade-extensions=<folder>`.

## Layout

| Folder | Content |
|---|---|
| `src/iur_ade_generator/` | the generators: `urospec.py` (specification model of the modules from the XSD, the JAXB classes and the schema mapping), `patch_binding.py`, `patch_mapping.py`, `gen_mapping.py`, `gen_citygml4j.py`, `gen_citydb.py`, `gen_fixture.py`, `compare.py`, `update_changes_*.py`, `cli.py` |
| `schemas/iur/urf/<version>/urbanFunction.xsd` | the urf schema of each edition as shipped in the PLATEAU datasets (Hachioji 2020 = 2.0, Kyoto 2024 = 3.0, Maebashi 2023 = 3.1, Osaka 2025 = 3.2); `regen_edition.sh` copies it into the citygml4j fork |
| `schemas/iur/urg/<version>/`, `schemas/iur/urt/<version>/` | the statistical grid and public transit schemas 2.0-3.2 from `https://www.geospatial.jp/iur/schemas/` (not supported yet; the forks keep urg/urt 1.4) |
| `java/roundtrip/` | Gradle project (composite build of `../../../iur-ade-citygml4j`): `gradlew run --args="<in.gml> <out.gml>"` reads a CityGML file with the ADE module and writes it back; `gradlew validate --args="<file.gml> <xsd>..."` validates against local XSDs |
| `java/ade-transform/` | Gradle project on the Importer/Exporter 5.5.0 + ADE Manager 2.3.0 class path: `gradlew run` (headless ADE Manager transformation), `gradlew register` (register an extension in a 3DCityDB, `-DdeleteScript=` dumps the delete functions), `gradlew commitOrder` / `gradlew tableWeights` (the batch commit order and the table weights the Importer/Exporter derives from a mapping) |
| `fixtures/` | `uro<ver>_building_all.gml`: one building using every building attribute field of the edition (hand-written); the generated `iur<ver>_all.gml` / `uro<ver>_all.gml` are written here by `regen_edition.sh` and not versioned |
| `tests/` | unit tests (`uv run pytest`); tests marked `integration` need the forks and the tools |
| `out/` | outputs of the verification runs (not versioned) |

## Design

- **Specification model.** `urospec` combines the XSD of every module (types, fields, generic application property
  hooks), the ade-xjc JAXB classes (exact accessor names and types) and the ADE Manager schema mapping (tables,
  columns, joins) into one model; types are kept per module and referenced by their qualified name across modules.
  Leading underscores of abstract types become the citygml4j `Abstract` prefix (`MODEL_RENAMES` lists the exceptions).
- **Every concrete urf feature is top-level.** PLATEAU writes them all as city object members; references between
  members (`urf:districtDevelopmentPlan`, ...) and `urf:target` are feature properties carrying an xlink, stored in join
  tables and exported as xlinks.
- **Join tables for multi-valued data type properties.** The Importer/Exporter orders its batch commits by table
  weights summed along the schema mapping joins in `int` arithmetic; one foreign key column per owner (the ADE
  Manager's layout) makes the weights of the shared uro data types overflow and scrambles the commit order. An owner
  with several list properties of one type keeps the foreign key columns, because the ADE Manager's delete functions
  reject two join tables between the same two tables.
- **Generated urf mapping.** The ADE Manager does not finish the transformation of the urban function hierarchy, so
  `gen_mapping` writes the mapping and DDL in its style: one table per type with fields, subtypes without fields share
  the base table, 25-character `ur_` identifiers, reserved words suffixed with `_`, cascading subtype keys.
- **Hooks of `core:_CityObject`** (3.2 `uro:pointCloud`) live in an injection table of `AbstractCityObjectType`
  (`ur_cityobject_2`); hooked features are stored as city objects of their own.
- **Lists** of simple values, measures and dates are stored as joined strings.

## Development

```bash
uv sync --dev
uv run pre-commit install
uv run ruff check && uv run ruff format --check && uv run mypy && uv run pytest
```

The generator modules were copied from the PoC workspace as they ran there; `pyproject.toml` lists the lint and type
rules they are exempted from until they are split into typed modules (the plan is task 13 of the investigation
documents).
