# iur-ade-generator

Code generators and verification harness for the i-UR ADE (PLATEAU, CityGML 2.0) extension of
[citygml4j](https://github.com/citygml4j/citygml4j) and the 3D City Database Importer/Exporter:

- [iur-ade-citygml4j](https://github.com/kei-w/iur-ade-citygml4j) (branches `iur-2.0`, `iur-3.0`, `iur-3.1`, `iur-3.2`)
- [iur-ade-citydb](https://github.com/kei-w/iur-ade-citydb) (the same branches)

The generators read the i-UR XSDs (`uro`, `urf`), the JAXB classes generated by ade-xjc and the 3DCityDB schema mapping,
and write the model classes, (un)marshallers, importers, exporters, schema registrations, the schema mapping of the
modules the ADE Manager cannot transform, a fixture file that uses every attribute, and the CHANGES sections of both
forks. The harness imports the fixture into a 3DCityDB, exports it again and compares the result.

The design is described in the investigation documents of the `plateau-citygml-ade-investigation` workspace (08: all
attributes, 11: ADE feature types, 12: urban function module); the main decisions are summarised in [Design](#design).

## Requirements

- Python 3.14 and [uv](https://docs.astral.sh/uv/) (`uv sync --dev` installs the Python version of `.python-version` and
  the development tools).
- The two forks checked out next to this repository (`../iur-ade-citygml4j`, `../iur-ade-citydb`, configurable); the
  commands switch them to the branch of the edition.
- JDK 11 for the forks and the Java harnesses (Gradle wrapper); the forks pin it with `mise`.
- For `regen`, `verify --db` and `recreate-db`: [ade-xjc 2.10.0](https://github.com/citygml4j/ade-xjc/releases), the
  [3DCityDB Importer/Exporter 5.5.0](https://github.com/3dcitydb/importer-exporter/releases) with the ADE Manager
  plugin 2.3.0, the SQL scripts of [3DCityDB 4.4.1](https://github.com/3dcitydb/3dcitydb/releases), a PostgreSQL/PostGIS
  server and `psql`. Their locations and the database connection are configured in `iur-ade.toml` (copy
  [iur-ade.example.toml](iur-ade.example.toml); every key can also be given as `IUR_ADE_<SECTION>_<KEY>` in the
  environment).

## Usage

```bash
uv sync --dev
cp iur-ade.example.toml iur-ade.toml   # and edit the tool folders and the database connection
uv run iur-ade --help
```

Regenerate one edition end to end (urf schema of the edition into the citygml4j fork, JAXB classes with ade-xjc,
schema mapping, code of both forks, builds, extension folder, fixture, fresh verification database, fixture round
trip, XSD validation):

```bash
uv run iur-ade regen 3.1
```

`--skip-jaxb` keeps the committed JAXB classes (no ade-xjc run), `--skip-db` stops after the fixture. The outputs
(logs, the exported fixture, the comparison report) go to `out/`.

Round-trip real CityGML files (folders recursively) through citygml4j with the ADE module, or with `--db` through a
fresh verification database, and compare each file with the result:

```bash
uv run iur-ade verify 3.1 ../_data/survey/maebashi-shi
uv run iur-ade verify 3.1 --db ../_data/survey/maebashi-shi ../_data/urf_survey/some_file.gml
```

`recreate-db <version>` drops and recreates the verification database of an edition and registers its extension
folder (what `regen` and `verify --db` do before importing).

The generator commands take the positional arguments of the modules they run:

| Command | Purpose |
|---|---|
| `iur-ade patch-binding <citygml4j repo>` | JAXB property renames in `binding.xjb` (feature types, urf package, `lod-N` elements) |
| `iur-ade patch-mapping <citydb repo> <citygml4j repo> <version> [modules]` | fixes of the ADE Manager output (idempotent): ifc choice/inline types, injections, top-level flags, join tables for multi-valued data types, cascading subtype keys, `core:_CityObject` hooks |
| `iur-ade gen-mapping <citydb repo> <citygml4j repo> <version> urf uro` | schema mapping and DDL of a module the ADE Manager cannot transform (urf 2.0/3.x), merged into the citydb resources |
| `iur-ade gen-citygml4j <citygml4j repo> <citydb repo> <version> all uro,urf` | model classes, JAXB (un)marshallers, walkers and modules |
| `iur-ade gen-citydb <citydb repo> <citygml4j repo> <version> all uro,urf` | importers, exporters, join table importers and schema registrations |
| `iur-ade fixture <citygml4j repo> <citydb repo> <version> all <out.gml> uro,urf` | a CityGML file with one feature per hooked CityGML feature type and per ADE feature type, every attribute populated |
| `iur-ade compare <original.gml> <roundtrip.gml> [--db] [--subset]` | semantic comparison of the city objects of two files (`--db` neutralises the known Importer/Exporter round-trip differences, `--subset` ignores extra objects) |
| `iur-ade changes-features ...`, `iur-ade changes-urf ...` | CHANGES.md sections of both forks (idempotent) |

The Importer/Exporter cannot load two editions of the extension at once, so they live in separate folders of the
Importer/Exporter installation (`ade-extensions-iur20` ... `ade-extensions-iur32`, created by `regen`) and are
selected with `--ade-extensions=<folder>`.

`scripts/tag_editions.sh` tags the four editions in both forks (annotated tags, local only) and builds their
distributions.

## Layout

| Folder | Content |
|---|---|
| `src/iur_ade_generator/` | `config.py` (editions, tools, database, workspace), `cli.py`, `regen.py`, `verify.py`, `database.py`, `tools.py` (subprocess wrappers), `naming.py` (Java and SQL identifiers) and the generators: `spec/` (the specification model: `xsd.py`, `jaxb.py` and `mapping.py` read the three sources, `model.py` holds the typed objects, `spec.py` links them), `mapping/` (`patch.py`: the fixes of the ADE Manager output, `generate.py`: the generated urf mapping, `ddl.py`: editing the DDL resources), `citygml4j/` (`model.py`, `bind.py`, `walker.py`, `module.py`, `generator.py`), `citydb/` (`tables.py`: the table model and dependencies, `fields.py`: the field code, `importer.py`, `exporter.py`, `join_tables.py`, `hooks.py`, `registry.py`: the registrations in the hand-written classes, `balloon.py`, `generator.py`), `binding.py`, `fixture.py`, `compare.py`, `changes.py` |
| `schemas/iur/urf/<version>/urbanFunction.xsd` | the urf schema of each edition as shipped in the PLATEAU datasets (Hachioji 2020 = 2.0, Kyoto 2024 = 3.0, Maebashi 2023 = 3.1, Osaka 2025 = 3.2); `regen` copies it into the citygml4j fork |
| `schemas/iur/urg/<version>/`, `schemas/iur/urt/<version>/` | the statistical grid and public transit schemas 2.0-3.2 from `https://www.geospatial.jp/iur/schemas/` (not supported yet; the forks keep urg/urt 1.4) |
| `java/roundtrip/` | Gradle project (composite build of `../../../iur-ade-citygml4j`): `gradlew run --args="<in.gml> <out.gml>"` reads a CityGML file with the ADE module and writes it back; `gradlew validate --args="<file.gml> <xsd>..."` validates against local XSDs |
| `java/ade-transform/` | Gradle project on the Importer/Exporter 5.5.0 + ADE Manager 2.3.0 class path (`-PimpexpHome=<folder>` or `IMPEXP_HOME`): `gradlew run` (headless ADE Manager transformation), `gradlew register` (register an extension in a 3DCityDB, `-DdeleteScript=` dumps the delete functions), `gradlew commitOrder` / `gradlew tableWeights` (the batch commit order and the table weights the Importer/Exporter derives from a mapping) |
| `fixtures/` | `uro<ver>_building_all.gml`: one building using every building attribute field of the edition (hand-written); the generated `iur<ver>_all.gml` are written here by `regen` and not versioned |
| `tests/` | unit tests (`uv run pytest`): the naming helpers, the configuration, the CLI, the comparison, the CHANGES sections, and the specification model and the generators on a small uro/urf module pair (`tests/data/mini`: XSDs, JAXB stubs, an ADE Manager style mapping) compared with golden files (`tests/golden/mini`, rewritten by `uv run pytest --update-golden`); tests marked `integration` regenerate the four editions and need the forks (`uv run pytest -m integration`) |
| `out/` | outputs of the verification runs (not versioned) |

## Design

- **Specification model.** `urospec` combines the XSD of every module (types, fields, generic application property
  hooks), the ade-xjc JAXB classes (exact accessor names and types) and the ADE Manager schema mapping (tables,
  columns, joins) into one model; types are kept per module and referenced by their qualified name across modules.
  Leading underscores of abstract types become the citygml4j `Abstract` prefix (`MODEL_RENAMES` lists the exceptions).
- **Every concrete urf feature is top-level.** PLATEAU writes them all as city object members; references between
  members (`urf:districtDevelopmentPlan`, ...) and `urf:target` are feature properties carrying an xlink, stored in join
  tables and exported as xlinks.
- **Join tables for multi-valued data type properties.** The Importer/Exporter orders its batch commits by table
  weights summed along the schema mapping joins in `int` arithmetic; one foreign key column per owner (the ADE
  Manager's layout) makes the weights of the shared uro data types overflow and scrambles the commit order. An owner
  with several list properties of one type keeps the foreign key columns, because the ADE Manager's delete functions
  reject two join tables between the same two tables.
- **Generated urf mapping.** The ADE Manager does not finish the transformation of the urban function hierarchy, so
  `gen_mapping` writes the mapping and DDL in its style: one table per type with fields, subtypes without fields share
  the base table, 25-character `ur_` identifiers, reserved words suffixed with `_`, cascading subtype keys.
- **Hooks of `core:_CityObject`** (3.2 `uro:pointCloud`) live in an injection table of `AbstractCityObjectType`
  (`ur_cityobject_2`); hooked features are stored as city objects of their own.
- **Lists** of simple values, measures and dates are stored as joined strings.
- **JAXB classes** are generated by ade-xjc from a copy of the fork's `resources/ade-xjc` folder (wrapper schema,
  binding, module schemas) in `out/ade-xjc/<version>`, with the imports of the GML/CityGML schemas pointed at the
  ade-xjc installation; all four packages are taken from one run because the `urt` classes refer to the `urf` feature
  classes, line endings are LF, and files that only differ by their generation timestamp are kept as committed.

## Development

```bash
uv sync --dev
uv run pre-commit install
uv run ruff check && uv run ruff format --check && uv run mypy && uv run pytest
```

The generator modules are type-checked by mypy in strict mode and linted by ruff; `pyproject.toml` only exempts the
template-heavy generator modules from the line length. Every change to a generator is checked twice: the golden
tests on the mini modules and the integration test that regenerates the four editions into the forks.
